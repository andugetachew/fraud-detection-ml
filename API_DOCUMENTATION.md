# API Reference

Base URL (local): `http://localhost:8088`
Interactive docs (auto-generated by FastAPI): `http://localhost:8088/docs`

## Authentication

Protected endpoints require an `X-API-Key` header matching the `API_KEY`
configured on the server.

```
X-API-Key: <your-api-key>
```

- If `API_KEY` isn't configured on the server at all, protected endpoints
  return `503` for every request (fails closed — never silently open).
- A missing or incorrect key returns `401`.
- `/health` and `/model/status` are intentionally public — no key needed.

## Rate limiting

Per client IP, via `slowapi`:

| Endpoint | Limit |
|---|---|
| `POST /predict` | 20/minute |
| `POST /predict/explain` | 10/minute (SHAP is heavier per request) |

Exceeding the limit returns `429`.

## `POST /predict`

Runs fraud inference on a single transaction. Auth required, rate-limited.

**Request body** — all fields required, matches the training dataset schema exactly:

| Field | Type | Notes |
|---|---|---|
| `Time` | float | Seconds elapsed since the first transaction in the dataset |
| `V1` .. `V28` | float | PCA-anonymized features |
| `Amount` | float | Transaction amount; must be `>= 0` |

```json
{
  "Time": 0,
  "V1": -1.36, "V2": -0.07, "V3": 2.54, "V4": 1.38, "V5": -0.34,
  "V6": 0.46, "V7": 0.24, "V8": 0.10, "V9": 0.36, "V10": 0.09,
  "V11": -0.55, "V12": -0.62, "V13": -0.99, "V14": -0.31, "V15": 1.47,
  "V16": -0.47, "V17": 0.21, "V18": 0.03, "V19": 0.40, "V20": 0.25,
  "V21": -0.02, "V22": 0.28, "V23": -0.11, "V24": 0.07, "V25": 0.13,
  "V26": -0.19, "V27": 0.13, "V28": -0.02, "Amount": 149.62
}
```

**Response `200`**
```json
{
  "is_fraud": false,
  "fraud_probability": 0.0002,
  "model_version": "v20260731_234212"
}
```

**Errors**
- `401` — missing/invalid API key
- `422` — payload fails validation (missing field, `Amount < 0`, wrong type)
- `429` — rate limit exceeded
- `503` — no `API_KEY` configured on the server

Notes:
- Prediction logging (for drift monitoring) happens asynchronously on the
  Celery worker after the response is sent — it does not add to response
  latency.
- Threshold: `is_fraud = fraud_probability >= 0.5`.

## `POST /predict/explain`

Same as `/predict`, plus a SHAP-based breakdown of which features drove
this specific prediction. Auth required, rate-limited (tighter — SHAP
computation is heavier than a plain inference).

**Request body** — identical to `/predict`.

**Response `200`**
```json
{
  "is_fraud": false,
  "fraud_probability": 0.0002,
  "model_version": "v20260731_234212",
  "top_features": [
    {"feature": "V14", "shap_value": -1.78763, "value": -0.31},
    {"feature": "V3",  "shap_value": -1.63255, "value": 2.54}
  ]
}
```

`top_features` — up to 10 entries, sorted by `|shap_value|` descending.
`shap_value` is the feature's contribution to the model's raw prediction
(negative pushes toward "not fraud", positive toward "fraud"); `value`
is the feature's actual (scaled, for `Time`/`Amount`) input value.

**Errors** — same as `/predict`.

## `GET /model/drift`

On-demand drift check: compares recent live prediction inputs against
the active model's reference sample, using Evidently's `DataDriftPreset`
(real statistical tests — KS-test/PSI depending on column type). Auth
required.

**Query params**
- `limit` (optional, default `500`) — max number of recent predictions to check against

**Response `200`**
```json
{
  "sample_size": 342,
  "is_drifting": false,
  "drifted_features": [],
  "drift_share": 0.03
}
```

If fewer than 30 recent predictions exist, statistical tests aren't
meaningful on that little data (a single point vs. a distribution will
almost always "fail"), so the check is skipped honestly rather than
producing a false alarm:

```json
{
  "sample_size": 3,
  "is_drifting": false,
  "drifted_features": [],
  "drift_share": 0.0,
  "insufficient_data": true
}
```

**Errors**
- `401` — missing/invalid API key
- `503` — no `API_KEY` configured on the server

## `POST /model/reload`

Reloads the active model in the worker process handling this request.
Auth required.

**Response `200`**
```json
{"reloaded": true, "version": "v20260731_234212"}
```

**Errors**
- `401` — missing/invalid API key
- `404` — no active model version found in the registry

⚠️ **Multi-worker caveat:** `api` runs 4 uvicorn worker processes (each
with its own in-memory model copy) for real concurrency. A single
`/model/reload` call only reloads whichever process handled that
request — it does not guarantee every process picks up the new version.
After activating a new model version, `docker compose restart api` is
the reliable way to make every worker process load it.

## `GET /metrics`

Prometheus-format metrics (unauthenticated — a scraper needs
network-level access control, not an API key meant for business
endpoints). Includes standard HTTP metrics (request count, latency
histograms, status codes per route) plus a custom business metric:
`fraud_predictions_total{is_fraud="true"|"false"}`.
